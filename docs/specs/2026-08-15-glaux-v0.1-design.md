# glaux v0.1 — Design Spec

*2026-08-15. Status: approved design, pre-implementation. Canonical copy also in Linear: project "glaux — v0.1: local Athena + Firehose data plane".*

## Problem

fakecloud (the leading post-LocalStack open-source AWS emulator, Rust, 105 services) deliberately implements only the **control plane** for analytics services:

- Its **Athena** has no SQL engine — no joins, CTEs, subqueries, aggregations, or window functions, and it never reads data files from S3. Unsupported queries return a **synthesized single-row result** (silently fake data).
- Its **Firehose** accepts `PutRecord` but "the bytes are dropped — no S3 object is written." Buffering, prefixes, and format conversion are configuration-only.

Result: data-engineering pipelines (the EventBridge → SQS → consumer → Firehose → S3 → Athena pattern) cannot be tested locally by any existing free tool. RustStack has neither service; LocalStack's Athena is paid, heavyweight, and janky.

## Product

**glaux** — the local data plane. Two real service implementations in Rust:

1. **Athena** — real SQL execution via Apache DataFusion over data in S3, with Glue Data Catalog metadata.
2. **Firehose** — real delivery: buffering, S3 object writes with prefix rules, and JSON→Parquet format conversion via Glue schemas.

**Core product value — never silently wrong:** any unsupported SQL construct or conversion fails loudly with a clear error naming the construct. The exact opposite of synthesized results.

Both services **consume** S3 and Glue rather than implementing them; endpoints are configuration, never assumptions. Supported targets: fakecloud in-process, fakecloud over HTTP, MinIO/other emulators (with catalog caveats), and **real AWS** (free side effect: run real queries against real S3 data without paying Athena per-query).

## Verified feasibility (2026-08-15 spikes, both passed)

- **fakecloud S3 ranged reads:** `GET` with `Range: bytes=100-107` and suffix form `bytes=-16` both return correct `206 Partial Content` with correct bytes and `Content-Range` — the access pattern Parquet readers require.
- **fakecloud embeddability:** fakecloud publishes ~109 crates; `fakecloud-core` exposes a public `AwsService` trait (`service_name` / `handle` / `supported_actions`), a public `ServiceRegistry::register` (re-registering a name **replaces** the service — glaux can swap out fakecloud's Athena stub), and a public `dispatch` axum handler. A PoC binary embedding fakecloud's real S3 plus a custom "athena" service on one port compiled and served both correctly.

## Workspace & licensing

| Crate | License | Purpose |
|---|---|---|
| `glaux-athena` | Apache-2.0 | Athena API + DataFusion execution engine |
| `glaux-firehose` | Apache-2.0 | Firehose API + delivery engine |
| `glaux-catalog` | Apache-2.0 | Glue catalog client + DataFusion catalog provider; S3 object-store backends |
| `glaux-server` | Apache-2.0 | Standalone binary: Athena+Firehose over HTTP, external S3/Glue endpoints |
| `glaux` | AGPL-3.0 | All-in-one binary: links fakecloud crates + glaux services, one port |

Apache-licensed code may be combined into the AGPL binary; the reverse dependency never happens (engine crates have zero fakecloud dependencies). S3/Glue access goes through a small internal trait with two backends: **network** (any endpoint) and **in-process** (direct fakecloud state calls, all-in-one binary only).

## Athena service design

**API surface (v0.1):** `StartQueryExecution`, `GetQueryExecution`, `GetQueryResults` (paginated), `StopQueryExecution`, `ListQueryExecutions`, `BatchGetQueryExecution`, basic workgroups. Faithful **async lifecycle** (`QUEUED → RUNNING → SUCCEEDED/FAILED`) so polling clients behave identically.

**Results fidelity:** like real Athena, results are also written as CSV + `.metadata` to the configured S3 `OutputLocation` — tooling that reads the CSV from S3 instead of calling `GetQueryResults` works unchanged.

**Execution:** Trino-dialect parse (`sqlparser-rs`) → translation → DataFusion logical plan. A **shim library** maps Trino functions DataFusion lacks or names differently (`date_parse`, `from_iso8601_timestamp`, `element_at`, `approx_distinct`, …). Every gap documented in an auto-generated coverage table; hitting one raises an explicit error naming the construct.

**Catalog:** `GlueCatalogProvider` implementing DataFusion catalog traits against the Glue API — databases, tables, columns, partitions. Hive-style partition pruning from Glue partition metadata. **Partition projection** (computed partitions, no Glue entries) included — common in real setups, cheap locally. SerDe mapping: Parquet SerDe → native; OpenX JSON SerDe → NDJSON reader; LazySimpleSerDe → CSV reader with configured delimiters.

**v0.1 SQL scope:** the full analytical SELECT surface — joins, CTEs, subqueries, window functions, GROUP BY/aggregations — over Parquet, JSON-lines, and CSV tables. No writes (v0.2), no Iceberg (v0.3).

## Firehose service design

**API surface (v0.1):** `CreateDeliveryStream`, `DescribeDeliveryStream`, `ListDeliveryStreams`, `UpdateDestination`, `DeleteDeliveryStream`, `PutRecord`, `PutRecordBatch`. Direct-PUT sources only (Kinesis sources later).

**Delivery engine:**

- Buffering honoring `BufferingHints` (`SizeInMBs` / `IntervalInSeconds`), flush on first threshold, per-stream tokio timers.
- S3 destination with real prefix semantics: default `YYYY/MM/DD/HH/` timestamping, custom `!{timestamp:...}` expressions, `ErrorOutputPrefix` for failed records, GZIP option.
- **Record format conversion:** JSON → Parquet using the Glue table schema configured on the stream (arrow-rs); schema-mismatched records go to the error prefix like real Firehose.
- v0.1 durability: in-memory buffers flushed on shutdown; durability knobs later.

## Configuration

One config story (file + env + flags) for both binaries: S3 endpoint, Glue endpoint, region/account, Athena defaults (`OutputLocation`, workgroup), Firehose limits. All-in-one binary defaults endpoints to in-process; `glaux-server` requires them.

## Testing & fidelity strategy

- **Differential suite vs real Athena:** query corpus (seeded from real workload patterns) recorded once against a sandbox AWS account (`--record`), snapshots checked in, CI replays offline and diffs normalized results. Same for Firehose artifacts (object keys, Parquet contents).
- **Auto-generated SQL coverage table** published in docs.
- **Flagship integration test:** the full EventBridge → SQS → consumer → Firehose → S3 → Athena pipeline scripted against the all-in-one binary in CI.
- Deep unit coverage where fidelity lives: dialect translation, prefix/buffering logic.

## Success criteria (v0.1)

1. Flagship pipeline runs end-to-end locally.
2. Real-world analytical query corpus matches real Athena results (normalized).
3. Zero silent wrong-results paths: unsupported constructs error explicitly.

## Roadmap

- **v0.1** — everything above.
- **v0.2** — CTAS, `INSERT INTO` (DataFusion writes → Parquet in S3 + Glue table/partition registration), `UNLOAD`.
- **v0.3** — Iceberg reads via iceberg-rust; MERGE/UPDATE/DELETE as the library matures.
- **Parallel cheap wins** — prepared statements, `EXPLAIN`, query runtime statistics; early contact with the fakecloud maintainer (possible future: glaux as fakecloud's official analytics engine).

## Out of scope (v0.1)

Writes (CTAS/INSERT), Iceberg, Kinesis-sourced Firehose, delivery durability guarantees, Lambda transforms in Firehose, federated query connectors, Athena notebooks/Spark.
